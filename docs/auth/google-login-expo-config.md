# Google Login (Expo) — Internal Configuration Reference

## Architecture

**Flow**: OAuth Authorization Code + PKCE (Option A from the guide).

1. Mobile app initiates Google OAuth with PKCE via `expo-auth-session`.
2. User authenticates in a secure in-app browser.
3. Google redirects back to the app via deep link (`athlifyr://redirect`).
4. App sends the authorization `code` + `codeVerifier` to the backend.
5. Backend exchanges the code with Google server-to-server, validates the ID token, finds/creates the user, and returns app session tokens (JWT).
6. Tokens are stored in `expo-secure-store`.

---

## Scheme

```
athlifyr
```

Configured in `mobile/app.json` → `expo.scheme`.

---

## Redirect URI

| Environment      | Redirect URI                                                          |
| ---------------- | --------------------------------------------------------------------- |
| Expo Go (dev)    | `exp://<host>:8081/--/redirect` (auto-generated by `makeRedirectUri`) |
| Dev build        | `athlifyr://redirect`                                                 |
| Production build | `athlifyr://redirect`                                                 |

The redirect URI is built at runtime by `AuthSession.makeRedirectUri({ scheme: "athlifyr", path: "redirect" })`.

> **Important**: The exact redirect URI used by the app must be registered in the Google Cloud Console under each OAuth client's "Authorized redirect URIs". For Android native clients using a custom scheme, this is handled automatically by the SHA-1 fingerprint + package name.

## Google Cloud Console — OAuth Client IDs

| Client  | Env Var (mobile .env)                  | Purpose                  |
| ------- | -------------------------------------- | ------------------------ |
| Web     | `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`     | Fallback / web platform  |
| Android | `EXPO_PUBLIC_GOOGLE_ANDROID_CLIENT_ID` | Android native PKCE flow |
| iOS     | `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID`     | iOS native PKCE flow     |

Backend env vars (Next.js `.env`):

| Var                           | Purpose                                        |
| ----------------------------- | ---------------------------------------------- |
| `GOOGLE_CLIENT_ID`            | Web client ID (server-side token exchange)     |
| `GOOGLE_CLIENT_SECRET`        | Web client secret (server-side token exchange) |
| `GOOGLE_ANDROID_CLIENT_ID`    | Android client ID (audience validation)        |
| `GOOGLE_IOS_CLIENT_ID`        | iOS client ID (audience validation)            |
| `GOOGLE_MOBILE_WEB_CLIENT_ID` | Mobile web client ID (audience validation)     |

## SHA-1 Fingerprints (Android)

Required in the Google Cloud Console → Android OAuth client:

| Key          | How to get                                                                                       | Where to add                    |
| ------------ | ------------------------------------------------------------------------------------------------ | ------------------------------- |
| Debug        | `keytool -list -v -keystore ~/.android/debug.keystore -alias androiddebugkey -storepass android` | Google Console → Android client |
| Release      | From your release keystore                                                                       | Google Console → Android client |
| Play Signing | Google Play Console → App signing                                                                | Google Console → Android client |

## Backend Endpoint

```
POST /api/auth/google/exchange
```

**Request body:**

```json
{
  "code": "<authorization_code>",
  "codeVerifier": "<pkce_code_verifier>",
  "redirectUri": "athlifyr://redirect",
  "platform": "android" | "ios" | "web"
}
```

**Response:**

```json
{
  "token": "<jwt_access_token>",
  "refreshToken": "<jwt_refresh_token>",
  "expiresIn": 604800,
  "user": {
    "id": "...",
    "email": "...",
    "name": "...",
    "role": "...",
    "image": "..."
  }
}
```

## Debugging Checklist

1. Print the `redirectUri` from the app logs — confirm it matches Google Console.
2. Confirm the correct client ID is used per platform (Android vs iOS vs Web).
3. Confirm SHA-1 fingerprints are registered for Android.
4. Confirm `scheme: "athlifyr"` is in `app.json`.
5. After `promptAsync()`, the browser should close and the `useEffect` on `response` should fire.
6. Check backend logs for exchange errors (`invalid_grant`, `redirect_uri_mismatch`).
